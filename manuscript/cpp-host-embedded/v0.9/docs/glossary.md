# 术语与定位

这里用于复查已经在正文展开的概念。条目给出本书用法和主要解释位置，不替代机制、平台限制或安全前提。相近名称只有在其契约一致时才可以互换。

## 设备与生产流程

**上位机。** 相对设备端而言，承担人机交互、流程组织、记录和外部系统对接的软件运行侧。它可能运行在普通PC或工业计算机上；这个相对位置不自动赋予实时性或安全控制资格。主解释见第1、10、14章。

**固件。** 与特定设备硬件密切结合、负责启动和设备行为的软件。固件也需要明确版本、接口、恢复和验证，不能因存放在Flash中就当作永远不变。见第1、17、20章。

**MCU。** 微控制器，通常在一个芯片上集成处理器、存储和外设。MCU型号决定可用资源与电气条件；“Cortex-M”只说明相关处理器系列，不能代替芯片完整料号。见第16至18章。

**PLC。** 可编程逻辑控制器，常用于工业设备的输入、逻辑与输出处理。程序组织和扫描、任务、通信调度由具体平台决定；普通PLC通信握手不是安全许可本身。见第1、13章。

**工件。** 当前被加工、测试或校准的对象。它的内部记录身份、外部序列号与其中电子节点的设备身份可能不同，开始测试以前需要核对它们的绑定。见第14、23章。

**工单。** 组织一批指定生产任务的业务记录，说明产品、数量、版本或路线等上下文。它不等于设备命令，也不等于某一件产品的检测结果。见第1、14、23章。

**工位与工站。** 工位强调流程中的作业位置；测试工站通常还包含执行测试的软件、仪器、连接与记录能力。本书使用station_id追溯实施位置，并在正文说明其范围。见第14、23章。

**治具。** 为装夹、定位、接触或测试特定工件而使用的辅助装置。治具磨损、接触和版本都可能影响结果，不能只把它当作一条线缆。见第14、23章。

**烧录。** 将程序或数据写入目标设备的非易失存储。写入成功、读回一致、固件正常启动和产品功能通过验收，是不同层次的完成证据。见第17、20、23章。

**校准与调整。** 校准依据参考建立量值与示值之间的关系；调整改变仪器或设备的响应。两者可以相关，但并非同义；调整之后仍需用合适的独立条件复核。见第16、23章。

**限值与判定规则。** 限值规定允许的数值边界，判定规则说明如何把测量值、不确定性及其他条件转成决定。两者都须带版本和适用条件，不应为了让样本通过而临时放宽。见第14、23章。

**复测。** 对同一工件再次执行测试。一次新尝试应保留新的attempt_id并关联先前记录，不用覆盖原失败结果的方法改善良率。见第14、23章。

**追溯。** 从结果找回对象、版本、条件、原始值、执行和确认过程的能力。仅保存一个PASS字符串不足以支撑追溯；记录需要能够解释当时为什么作出这个判断。见第14、23章。

**MES与ERP。** MES组织制造执行、工艺路线和生产结果等信息；ERP覆盖更广的企业资源与业务计划。二者与工站之间传递的工单、路线和结果仍需明确契约，不是一条数据库连接就自动完成集成。见第1、14、23章。

## C++ 数据与资源

**对象生命期。** 对象按语言规则存在并可被相应方式使用的时间区间。它与名字的作用域、空间的存储期不同；仍保存着一个地址不能证明目标对象还活着。见第2章。

**所有权。** 对释放、销毁或结束某项资源承担主要责任。访问指针、Qt线程归属和资源所有权分别描述不同关系，应在接口里独立说明。见第2、7、11、18章。

**借用。** 在约定范围和期限内访问由他人管理的对象或资源。引用、裸指针、string_view和span常表达某种借用，但它们不会自动延长目标寿命。见第2、3章。

**RAII。** 将资源获取及清理责任绑定到对象的初始化与析构规则。它既可管理内存，也可管理文件和设备句柄；业务提交、失败恢复与远端确认仍需要显式契约。见第2章。

**移动语义。** 类型规定的资源或状态转移。std::move主要产生允许选择相应重载的表达式，不保证发生搬运，也不保证源对象变成某个统一的值。见第2、3章。

**size与capacity。** size表示容器当前元素数，capacity表示在适用操作范围内无需重新分配即可容纳的元素数。预留空间不是提前构造了同等数量的元素。见第3章。

**失效。** 某些操作使已有指针、引用、迭代器或视图不再能按原方式使用。是否失效由具体类型与操作规则决定，不能仅看内存地址似乎有没有变化。见第3章。

**数据竞争。** 按C++规则，未建立必要同步的冲突访问可能形成数据竞争并导致未定义行为。偶尔得到正确数值、加上volatile或降低优化，都不是修复依据。见第6、18章。

**发布与回收。** 发布让接收者在必要同步关系下观察到已准备好的数据；回收使生产者知道最后读取已经结束，可以复用空间。只完成发布而没有回收条件仍可能覆盖正在读的数据。见第6、18章。

**ABI。** 应用二进制接口，包括调用约定、符号、布局和运行时边界等规则。头文件能编译不证明与某个预编译库兼容；编译器、架构和库配置都可能参与。见第5章。

**交叉编译。** 在一类主机环境中生成另一目标平台运行的程序。主机上能执行编译器，与目标系统能装载产物，是两件事；还需目标库、启动及链接条件。见第5、17、21章。

## 通信 线程与确认

**协议帧。** 按约定组织的一条消息，包括边界、字段和检查条件。本书温度帧最多76字节；C++结构体的原始内存不是它的定义。见第4、12章。

**字节序。** 多字节值在字节序列中的高低有效部分排列规则。它不同于串口的位发送次序，也不同于CRC输入是否反射。见第4章。

**CRC。** 一类循环冗余校验方法，按明确参数和覆盖范围形成检错值。参数、初值、反射、结果异或及存储顺序都应给全；CRC不能替代认证或安全论证。见第4、12章。

**会话代际。** 本书generation字段用于区分主机建立的新旧连接实例。它帮助拒绝迟到消息，但不提供原子同步，也不取消对端已经执行的动作。见第11、12章。

**命令身份。** command_id标识同一个业务动作，使未知结果可以查询、核对或按契约重试。每次网络重连都换一个新command_id，可能把一次重试变成第二次执行。见第12至14、23章。

**线程归属。** QObject由哪个线程的事件循环处理事件。它不等于C++变量定义在谁的成员里，也不等于QThread对象所管理的线程。见第10、11章。

**事件循环。** 按框架规则取出并派发事件的执行组织方式。一个槽长期占用线程时，该线程的后续事件就可能得不到处理；排队连接不会自动为每个消息新建线程。见第10、11章。

**背压。** 消费速度不足时，把容量或进展限制传回上游，使系统减速、拒绝或停止，而不是无界积压。追溯记录与最新显示快照可以采用不同策略。见第3、6、11章。

**超时与未知。** 超时表示在指定期限内没有观察到所需结果，不自动证明动作未执行。无法区分成功与失败时，应表达Unknown并按身份核查。见第7、12、23章。

**取消请求。** 请求操作按契约停止继续工作。发出请求不等于完成，调用者通常还需要等待最后一次访问、回调或硬件活动结束的证据。见第6、11、18章。

**Outbox。** 与本地结果一起持久记录的待发送信息，使进程恢复后仍知道哪些结果需要提交。它解决本地持久化与外部提交之间的一部分衔接，不能凭名称保证接收方去重。见第14、23章。

**幂等与去重。** 幂等关注重复操作是否产生相同可观察效果；去重利用身份等记录拒绝或合并重复处理。它们有具体存储、范围和保留期限，不能只靠一次内存集合查询保证永久成立。见第12、14、23章。

## 板卡 固件与 Linux

**位号 BOM 网络名。** 位号关联板上器件与图纸，BOM列出物料身份，网络名关联电气节点。三者配合才能从照片走到可核查的器件和连接；位号不是完整料号。见第16章。

**逻辑阈值。** 接收器判定输入高低的电压边界。阈值、电源标称值、允许工作范围和绝对最大额定值不同，不能用其中一个替代全部电气检查。见第16、17章。

**收发器。** 在控制器逻辑侧与特定物理线路之间转换电气信号的器件。UART控制器、RS-485收发器和连接器各有自己的职责。见第12、16、17章。

**中断与ISR。** 外设或系统事件触发相应异常处理的机制，ISR是中断服务程序。ISR需要受限、可说明的工作量，并遵守端口允许调用的接口范围。见第18章。

**DMA。** 直接内存访问机制，按配置在外设与存储等位置之间搬运数据。它减轻逐项CPU搬运，不自动拥有C++对象寿命，也不替软件保存被覆盖的旧数据。见第18章。

**实时性。** 指定结果在要求的时限内产生并符合其正确性条件。平均速度快、使用RTOS或提高优先级，都不足以单独证明实时性。见第1、19、24章。

**优先级反转。** 高优先级任务因依赖低优先级持有的资源而等待，其他任务还可能延长等待。优先级继承缓解其中一些干扰，不能代替完整资源依赖与时限分析。见第19章。

**看门狗。** 在规定条件下未获得适当维护时触发恢复动作的监督机制。无条件定时喂狗可能掩盖业务停滞，监督应对应关键进展而不是只证明一个定时器仍在动。见第20章。

**BSP。** 板级支持包，包含使操作系统或运行环境适用于特定板卡的支持工件与配置。具体内容随平台而异，不只是一个应用链接库。见第21章。

**设备树。** 描述特定硬件及资源关系的数据结构。DTS源码、编译后的DTB和运行时实际加载的设备树是不同阶段；节点存在也不保证驱动成功probe。见第21、22章。

**设备节点。** Linux用户态通过文件系统名称进入某些设备接口的入口。名称和权限并不包含设备的全部行为；read、write、poll或ioctl语义仍由具体接口规定。见第22章。

**用户态与内核态。** 对应不同执行权限与责任边界。普通应用通过系统调用访问内核提供的接口；本书不把用C++写Linux内核驱动作为默认路线。见第21、22章。

**测量证据。** 在明确仪器、接线、参考、触发和适用范围下记录的观察。日志、逻辑分析、示波器与万用表分别能支持不同判断，照片或教学波形不能冒充现场测量。见第8、16、23、24章。
