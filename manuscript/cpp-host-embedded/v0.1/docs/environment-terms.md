# 示例环境与术语约定

## 已使用的说明基线

- C++：C++20概念基线；平台特定资源以明确标注的SDK契约说明，不暗示Windows HANDLE、POSIX文件描述符或厂商句柄可互换
- Qt：Qt 6.8 API文档及Qt 6.8.3关键退出实现静态核对；桌面主线为Qt Widgets、QObject工作对象和异步QSerialPort。没有固定并运行一套编译器、Qt补丁、驱动与操作系统镜像的可执行验证环境
- 平台：Windows为主讲环境、Linux为第二验证目标；“验证目标”不是已通过验证
- 数据：temperature_mC以毫摄氏度计，sequence为样本序号，generation为连接会话代际。示例类型只在进程内使用，不定义网络字节序、报文布局、校准版本或持久化格式
- MCU：Cortex-M类MCU为全书主路线；本样章的STM32F4 Discovery照片只用于外观认知。最终硬件主实现链及其精确料号、板修订与工具链仍需冻结

## MCU主实现链的候选与验证前提

后续N17至N20宜选定一块具有公开完整原理图、稳定调试路径和UART引出的Cortex-M教学板，配一个资料完整的低压温度传感器；先完成GPIO与UART，再接入中断、DMA和一种FreeRTOS类内核。此处是一条候选实施链，不代表本轮已经采购、选定或连接具体硬件。

冻结环境时必须同时记录：芯片完整料号和硅修订、板卡与传感器模块修订、供电方式、调试器及逻辑电平、UART适配器、固件库和内核版本、编译器、链接脚本、构建参数、异常与RTTI策略，以及文档和勘误版本。接线图和可复现实验记录应与该身份绑定。

硬件验证至少分开建立三类证据：静态构建及内存预算；在指定板卡上的功能/故障行为；在指定负载和仪器条件下的电气、时序及功耗测量。桌面编译成功或仿真通过均不能替代后两类。本轮没有这些证据，不能开放全书硬件“实测通过”的门槛。

## 核心术语的一致用法

| 术语 | 本册含义 | 不应混淆的概念 |
| --- | --- | --- |
| 对象生命期 | 对象可按语言规则使用的那段时间 | 名字可见的作用域、承载它的存储期 |
| 所有权 | 对释放或结束资源负主要责任 | 有一个可访问的指针、QObject线程归属 |
| 借用 | 在约定条件内访问他人管理的资源 | 自动延长资源生命期 |
| RAII | 用对象初始化和清理责任管理资源 | 仅限堆内存、必然完成业务提交 |
| 移动 | 类型规定的资源或状态转移 | std::move调用本身已经搬运 |
| 线程归属 | QObject由哪个线程的事件循环处理事件 | 变量放在哪个对象里、QThread所管理的线程 |
| 取消请求 | 请求任务尽快按契约停止 | 任务已完成、全部回调已退出 |
| 会话代际 | 区分新旧连接的一次性身份值 | 原子同步、设备序列号、样本序号 |
| 位号 | 图纸、BOM与板上位置关联的编号 | 完整料号、额定值或唯一硬件身份 |
| 网络名 | 同一电气节点在图纸中的名称 | 未核对便可相连的任意“地” |
| 阈值 | 接收器识别高低状态的输入边界 | 电源标称值、绝对最大额定值 |
| 校准 | 依据参考建立测量值与量值的关系 | 调到看似合理的值、已经符合生产限值 |

这些约定先在首次出现处解释，再在此表归并；术语表不能替代章节机制。后续批次若改变数据字段或环境，需要同时更新正文、图像、例子与修订记录。
