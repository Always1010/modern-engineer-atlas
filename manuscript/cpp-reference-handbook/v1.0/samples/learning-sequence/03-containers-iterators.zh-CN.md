# 容器与迭代器

当记录数量会变化时，需要一个能够保存和组织多个元素的对象。本节先用 `vector` 保存整数，观察长度和容量，再建立访问位置的模型，最后判断容器修改后哪些位置仍然有效。

适用范围：C++17。阅读前需要掌握变量初始化、`auto`、数组下标、引用、对象生命周期、`if`、普通 `for` 与范围 `for`。异常基础可在上一组样稿中获得。下面的操作放在函数体内，按每个例子说明的头文件准备声明；各例分别理解。

## vector 与元素

**容器**（container）拥有或组织一组元素，并提供访问和修改操作。**`std::vector`** 保存长度可变的一组同类型元素；一般 `vector` 的元素连续存储。本节使用 `int`，不涉及 `vector<bool>` 的特殊形式。

下面需要 `<vector>`。`std::vector<int>` 中的 `<int>` 指定元素类型：

```cpp
std::vector<int> values{10, 20, 30};
int first = values[0];  // 10
values[1] = 25;
values.push_back(40);
```

最后序列是 `10、25、30、40`。下标从零开始；`push_back` 在末尾建立一个新元素，长度由三变为四。局部容器离开作用域时，其元素被销毁，所管理的存储按相应规则释放。

## 长度与访问边界

**长度**表示当前已经存在的元素数量，由 `size()` 查询。`empty()` 判断是否没有元素。`operator[]` 不检查越界，`at()` 检查下标并在越界时抛出 `std::out_of_range`。

下面是新的局部例子，需要 `<vector>`：

```cpp
std::vector<int> values{10, 20, 30};
auto length = values.size(); // 3
bool empty = values.empty(); // false
int last = values.at(2);     // 30
// values[3];               // 越界，不读取
```

三个元素的有效下标是 `0、1、2`。即使某块内存看起来还在，也不能访问没有相应元素的下标。`size()` 返回容器的无符号长度类型；空容器的长度为零，不应先做 `size() - 1` 再尝试访问最后一个元素。

## 容量、reserve 与 resize

**容量**表示在不重新分配存储的情况下，可以容纳多少元素，由 `capacity()` 查询。容量至少等于长度；已经预留的空间不等于已经建立的元素。

下面需要 `<vector>`：

```cpp
std::vector<int> values{10, 20, 30};
values.reserve(6);
auto after_reserve = values.size(); // 3
values.resize(5);
auto after_resize = values.size();  // 5
int added = values[4];              // 0
```

`reserve(6)` 要求容量至少为六，没有建立第四至第六个元素。`resize(5)` 才把长度改为五；对于这个默认分配器的 `vector<int>`，新增两个整数得到零值，因此序列为 `10、20、30、0、0`。

容量不一定恰好为请求的数值。这里只根据标准承诺判断“至少”，不猜测某个实现的增长倍数。长度和容量清楚之后，才能讨论重新分配对已有访问关系的影响。

## 范围 for 与逐个访问

先用已经学过的范围 `for` 处理每个元素，无需显式保存访问位置。下面需要 `<vector>`：

```cpp
std::vector<int> values{10, 20, 30};
int total = 0;
for (int value : values) {
    total += value;
}
```

`total` 最后是 `60`。这里 `value` 是当前元素的整数副本。若要修改元素，可以在一个新的遍历中写 `int& value`，让循环变量借用当前元素。先掌握逐个访问，再学习算法如何保存和返回某个访问位置。

## 迭代器、begin 与 end

**迭代器**（iterator）表示序列中的访问位置。对本例的 `vector<int>`，`begin()` 取得第一个元素的位置，`end()` 取得最后一个元素之后的**尾后位置**。

迭代器通过 `*it` 访问当前位置的元素，通过 `++it` 前进一个位置。这里的接口写法与指针相似，但不要据此假定所有容器的迭代器都是裸指针。

![三个元素及它们的访问位置](resources/iterator-positions.svg)

图：`begin` 指向 `10`，向前走三次到达 `end`。尾后位置用于判断结束，本身没有可供读取的元素。

下面需要 `<vector>`：

```cpp
std::vector<int> values{10, 20, 30};
auto it = values.begin();
int first = *it;  // 10
++it;
int second = *it; // 20
```

这个序列非空，所以可以读取第一个位置；前进后还没有到尾后位置，因此第二次读取有效。对空容器，`begin() == end()`，不能解引用起点。

## 半开区间与遍历终点

**半开区间** `[first, last)` 包含起点所指元素，不包含终点位置所指元素。整个容器的常用区间是 `[begin(), end())`。

下面需要 `<vector>`，用显式位置完成前面的求和任务：

```cpp
std::vector<int> values{10, 20, 30};
int total = 0;
for (auto it = values.begin(); it != values.end(); ++it) {
    total += *it;
}
```

循环体每次先经过 `it != end()` 的判断，只有存在当前元素时才解引用。遍历到尾后位置就结束，结果仍为 `60`。空容器会在第一次判断时直接结束。

起点与终点必须构成有效区间；这里都来自同一个仍然存活、遍历中没有被修改的容器。不能把两个不同容器的位置拼成一个区间。

## 指定插入和删除位置

有了位置模型，就能说明“在第二个元素前插入”与“删除第二个元素”。`vector` 的迭代器支持 `begin() + n` 定位；这里的非负偏移 `n` 应不超过 `size()`，只能到达元素位置或尾后位置，到达尾后位置后不能解引用。这项导航能力不能直接推广到链表。

下面需要 `<vector>`，插入与删除的返回值分别是新插入元素的位置和删除位置之后的新位置：

```cpp
std::vector<int> values{10, 30};
auto inserted = values.insert(values.begin() + 1, 20);
int new_value = *inserted; // 20，序列为 10、20、30
auto next = values.erase(inserted);
int following = *next;    // 30，序列为 10、30
```

本例删除的不是末元素，所以返回的新位置指向 `30`，可以读取。若删除末元素，返回值会是新的 `end()`，应先检查再读取。插入位置允许为 `end()`，单元素删除位置则必须指向已有元素，不能删除尾后位置。

## 容器修改与迭代器失效

容器修改可能让以前保存的位置无法继续用于原来的元素访问，这称为**迭代器失效**。它不要求旧迭代器的数值变为空，也不能通过“试着读取一次”确认它仍有效。

先看销毁全部元素。`clear()` 销毁容器中的全部元素，长度变为零，因此以前保存的元素迭代器全部失效。下面需要 `<vector>`：

```cpp
std::vector<int> values{10, 20, 30};
auto old = values.begin();
values.clear();      // 销毁全部元素
// 不再使用 old
values.push_back(40);
auto current = values.begin();
int first = *current; // 40
```

重新加入元素后，应重新取得位置；即使原来的底层存储被继续使用，也不能把旧位置当作仍有效的借用。

重新分配则是另一种使全部旧元素迭代器、指针和引用失效的情况。`reserve(n)` 在 `n` 超过当前容量且调用成功时会重新分配；尾部追加是否重新分配要看当时容量。调用可能因分配失败抛异常，这里描述的是成功操作的失效规则。

删除则有另一种失效范围：

```cpp
std::vector<int> values{10, 20, 30}; // 需要 <vector>
auto first = values.begin();
auto erased = values.begin() + 1;
auto next = values.erase(erased);
int kept = *first;   // 10，删除点之前的位置保留
int following = *next; // 30，使用返回的新位置
// 不再使用 erased，也不沿用删除点之后的旧迭代器
```

删除点之前的元素位置保留，删除点及之后的旧迭代器失效。原来某个下标处的业务记录也可能改变，所以“下标还能访问”与“仍代表原来的记录”需要分别判断。

| vector 操作 | 旧元素迭代器 | 旧 end |
| --- | --- | --- |
| 成功重新分配 | 全部失效 | 失效 |
| 尾部追加，没有重新分配 | 保留 | 失效 |
| 中间插入，没有重新分配 | 插入点之前保留，其余失效 | 失效 |
| 删除非空范围 | 删除点之前保留，其余失效 | 失效 |

这张表是在具体位置和修改例子之后整理规则。其他容器各有自己的保证，不能拿它代替 `deque`、`list` 或关联容器的规则。

## 算法返回位置

算法可以接收区间，并返回一个访问位置。**`std::find`** 在 `[first, last)` 中寻找与给定值相等的第一个元素；找不到就返回 `last`。下面需要 `<algorithm>` 和 `<vector>`：

```cpp
std::vector<int> values{10, 20, 30};
auto found = std::find(values.begin(), values.end(), 20);
if (found != values.end()) {
    *found = 25;
}
```

最后序列为 `10、25、30`。先判断结果不是尾后位置，再读取或修改元素。至此，容器提供存储，迭代器表达位置，算法处理区间，三者可以连接起来。

## 理解检查与后续规则

三个元素的容器在 `reserve(6)` 后是否有六个元素？`end()` 是否是最后一个元素？删除某个元素后为什么要优先使用返回的新位置？

长度仍是三；`end()` 在最后一个元素之后，不能解引用；原删除点及之后的旧迭代器失效，返回值提供修改后可以继续使用的位置，但仍需检查它是否等于新尾后位置。
