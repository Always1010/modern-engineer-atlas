# 第5章 指针与引用

**版本**：C++17；C++20 聚合的圆括号初始化例外单独说明。**先修**：R02至R04。首次阅读第1至3节；返回借用和临时对象例外应在设计接口前完整检查。指针、引用和视图通常借用对象，并不负责保活；“非空”“地址未变”“类型正确”都不足以单独证明一次访问合法。

## 1 指针和引用各自表达什么

| 形式 | 语义 | 适合表达的接口条件 |
| --- | --- | --- |
| `T*` | 可以改变所指对象，也可以为空 | 可选借用；另行约定是否拥有及长度 |
| `const T*` | 通过它不可修改所指 T | 只读借用；指针本身可重新指向 |
| `T* const` | 指针本身不可重新指向 | 仍可以通过它修改非 const 的 T |
| `T&` | 必须初始化，绑定后不重新绑定 | 必选借用；赋值修改所指对象 |
| `const T&` | 只读绑定，也可绑定某些临时 | 不代表借用一定长寿 |
| `T&&` | 通常绑定右值 | 可被移动的参数或推导中的转发引用 |

nullptr 是专门的空指针常量，避免用整数 0 引入重载歧义。引用没有可用来表示“无对象”的合法空状态；通过空指针构造引用不能补出一个对象。对象别名不会带来独立的对象寿命或同步。[引用声明](https://timsong-cpp.github.io/cppwp/n4659/dcl.ref)、[引用初始化](https://timsong-cpp.github.io/cppwp/n4659/dcl.init.ref)。

默认初始化的自动局部裸指针可能没有确定值，不能先写 if(p) 来尝试确认它是否可用；声明时给 nullptr 或立即绑定一个有效地址。对已初始化的指针，非空只排除了空状态，仍可能悬垂、越界或指向错误类型。拥有指针优先封装进资源类，借用裸指针则要能追踪对应所有者。

多级指针的 const 规则要逐层分析。`T**` 不能直接转成 `const T**`，否则可能把 const 对象指针写回一个可修改对象的指针槽。不要用 cast 消除这一保护；改清楚接口的每一层权限。

## 2 指针算术只在合法数组区间内

数组 a 的可用位置是元素 [0,N)，尾后位置 a+N 可形成、比较并作区间终点，但不可解引用。指针加减必须保持在同一数组或其尾后范围；两个指针相减要求来自同一数组且差值可由 ptrdiff_t 表示。非数组单个对象为这些规则视作长度一的数组，不把连续碰巧相邻的两个变量变成数组。[指针加减](https://timsong-cpp.github.io/cppwp/n4659/expr.add)。

指针参数只携带地址。本章 find_value 约定 first、last 构成同一数组的有效半开区间，且元素初始化完毕；它无法从两个任意地址验证该契约。生产接口可用容器或 C++20 span 保留范围信息，但 span 仍不拥有底层对象。长度计算及空区间必须与调用者约定一致。

## 3 临时对象延长寿命：允许路径与例外

局部 `const T& r = T{};` 或 `T&& r=T{};` 的直接绑定可把临时对象寿命延长到引用的寿命；特定成员访问等表达式还可延长完整临时对象。把这个引用再绑定到另一个引用不会继续延长临时寿命。[临时对象](https://timsong-cpp.github.io/cppwp/n4659/class.temporary)。

![临时对象与借用的寿命时间线](../resources/R05-borrow-timeline.svg)

图5-1：直接局部绑定的临时跨过分号；函数参数绑定的临时只到调用所在完整表达式末尾。横轴是语义事件，非真实耗时；优化不能把悬垂借用变成合法访问。

几个例外尤其容易漏查：返回语句中绑定返回引用的临时在返回表达式结束时销毁；函数引用形参绑定的临时只活到调用所在完整表达式结束；new 初始化器中的引用成员不把临时延长到动态对象的寿命。构造函数成员初始化器把引用成员绑定到临时是非法程序，不能依赖某编译器扩展。

C++20 聚合含引用成员时，花括号初始化可按规则延长寿命，圆括号初始化中的临时只到完整表达式末尾，二者不能互换。[C++20 临时例外](https://timsong-cpp.github.io/cppwp/n4861/class.temporary)、[C++20 初始化](https://timsong-cpp.github.io/cppwp/n4861/dcl.init)。

“引用绑定到临时”还不足以推出延长寿命，必须看产生临时和绑定的表达式是否属于规定路径。例如通过返回引用的访问函数取出临时所有者内部成员，再绑定到局部 const 引用，不会因为这个新名字而重新保活所有者。直接成员访问与调用成员访问函数可能有不同结论；不熟悉路径时先给所有者一个有清晰作用域的名字。

## 4 返回借用、成员借用与别名约束

返回局部对象的指针或引用会悬垂；返回调用者传入对象的成员借用，则要求调用者维持整个所有者及成员的寿命，并避免会使借用失效的修改。返回类型是 const T& 也无法修复所有者提前销毁。例如取得临时 string 的 data 后保存指针，跨过分号便不可再读。

接口文档应写清借用到何时、哪些操作会使其失效、是否允许空值及并发访问条件。对有身份的业务对象，还要区分地址有效与逻辑身份未变。std::vector 删除或重分配导致的失效见 R13。

把非拥有成员放入可复制类时，默认复制会复制借用关系。新对象并没有取得原所有者的独立副本，两者可能指向同一个外部对象；移动这样的类也不必改变借用目标。若类要自足，应保存值或拥有者；若类刻意作为视图，则禁止它比所有者活得久，并避免对调用者造成“复制之后就安全”的错觉。

严格别名规则约束通过何种类型访问对象。把 float 的地址强转成 int* 读取位模式并不因大小相同就合法；优先使用合法字节观察、memcpy 或 C++20 bit_cast，且检查目标类型条件。对象寿命与重新使用存储的高级规则见 R02、R09。[类型访问](https://timsong-cpp.github.io/cppwp/n4659/basic.lval)。

## 5 工作例子与失败边界

与 `examples/r05-pointers-references.cpp` 一致；使用 R01 的 C++17 命令。预期 `found=5 kept=alive`，检查失败返回非零。失败查找返回 nullptr，不访问不存在的元素。

```cpp
#include <iostream>
#include <string>

struct Owner { std::string text; };

int* find_value(int* first, int* last, int wanted) {
    for (; first != last; ++first) {
        if (*first == wanted) return first;
    }
    return nullptr;
}

int main() {
    int values[]{2, 4, 6};
    int* found = find_value(values, values + 3, 4);
    if (!found || *found != 4) return 1;
    *found = 5;
    if (values[1] != 5 || find_value(values, values + 3, 9)) return 2;
    const Owner& kept = Owner{"alive"};
    if (kept.text != "alive") return 3;
    std::cout << "found=5 kept=alive\n";
}
```

kept 的绑定延长 Owner 临时的寿命，直到 main 的相应作用域结束。若把这次构造移进一个返回 const Owner& 的函数，结论便不成立；本例不执行该错误。find_value 返回的地址只在 values 存活且对应元素身份有效时可用，函数退出不会销毁调用者的数组。资源所有者见 R09，值类别见 R04。
