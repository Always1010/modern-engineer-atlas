# 第1章 程序结构与第一次编译

**版本**：C++17；文中命令使用现有 Windows PowerShell 和 GCC 10.3。**先修**：无。首次阅读先完成第1、2节，接手多文件项目时再查第3至5节。一个程序能运行，需要源码合法、所需定义能被链接器找到，并满足运行时规则；三个阶段的成功不能相互替代。

## 1 从一个可检查的程序进入

保存下面程序为配套文件 `examples/r01-program-build.cpp`。头文件 `<iostream>` 声明标准输入输出设施，`std::` 限定名字来自标准命名空间。`int main()` 是本例的程序入口；正常返回零表示成功，非零表示检查失败。这里在调用前写出函数声明，函数体是稍后的定义，二者的参数与返回类型必须一致。

```cpp
#include <iostream>

int twice(int value);

int main() {
    const int result = twice(21);
    if (result != 42) {
        std::cerr << "check failed\n";
        return 1;
    }
    std::cout << "result=" << result << '\n';
    return 0;
}

int twice(int value) {
    return value * 2;
}
```

在本版本目录运行现有编译器，不需要安装工具。D:/tdmgcc/bin/g++.exe 是本机核验路径；其他读者将它替换为自己已有的 g++ 路径。全新检出没有 qa 目录时，先创建本版本内的输出目录：

```powershell
New-Item -ItemType Directory -Force qa | Out-Null
& 'D:/tdmgcc/bin/g++.exe' -std=c++17 -Wall -Wextra -Wpedantic examples/r01-program-build.cpp -o qa/r01-program-build.exe
if ($LASTEXITCODE -ne 0) { throw 'compile failed' }
& ./qa/r01-program-build.exe
if ($LASTEXITCODE -ne 0) { throw 'run failed' }
```

预期输出为 `result=42`。输出和退出码都应核对；“生成了 exe”不能证明计算正确。当前程序的乘法输入固定在 int 可表示的范围内，它没有提供任意输入的溢出检查。可移植入口使用返回 int 的 main，不使用 `void main`。[main 的要求](https://timsong-cpp.github.io/cppwp/n4659/basic.start.main)。

## 2 构建究竟做了什么

翻译单元是预处理后的一个源文件及其所包含内容。头文件通常通过 `#include` 进入每个使用它的翻译单元，并非天然独立编译一次。预处理处理包含、宏和条件分支；编译检查名字、类型、语义并产生目标代码；链接解析跨单元引用并组合库。本图是概念流程，GCC 等工具可以把多个阶段合并执行。[翻译阶段](https://timsong-cpp.github.io/cppwp/n4659/lex.phases)。

![翻译单元如何成为程序](../resources/R01-build-pipeline.svg)

图1-1：箭头表示依赖和构建产物，不保证编译器内部必须生成每个中间文件。公共头进入两个翻译单元，因此其中的定义必须满足重复定义规则。

GCC 的 `-E` 只预处理，`-c` 编译到目标文件而不链接；本例也可先用 `-c ... -o qa/r01-program-build.o`，再把该目标文件传给 g++ 链接。链接使用 g++ 驱动，可让驱动加入 C++ 运行库。修改头文件后，应重新编译依赖它的翻译单元；增量构建工具负责追踪这类依赖。

## 3 声明、定义与链接属性

| 写法或位置 | 解决的问题 | 应检查的边界 |
| --- | --- | --- |
| `int f(int);` | 让当前单元知道调用接口 | 本身没有函数体，使用时通常还需要定义 |
| `int f(int x) { return x; }` | 提供函数实现 | 普通外部函数不能在多个单元重复定义 |
| `extern int count;` | 声明其他位置的变量 | `extern int count = 0;` 仍是定义 |
| 命名空间作用域 `static` 或匿名命名空间 | 把实体限制在当前翻译单元 | 两个单元各有独立实体 |
| C++17 `inline` 变量或 inline 函数 | 允许满足 ODR 条件的多单元定义 | inline 不是强制机器码内联的承诺 |

作用域回答“这个名字在哪里可见”；链接属性回答“不同单元的名字是否指同一实体”，二者不同。命名空间用于组织和限定名字，不能自动修复重复定义。公共头应包含自足的接口依赖，避免要求包含者先碰巧包含别的头。[链接属性](https://timsong-cpp.github.io/cppwp/n4659/basic.link)。

标准头用尖括号，项目头通常用双引号；查找的具体路径受实现及编译选项控制，不由文件扩展名决定。头文件包含保护可用唯一宏包围全部内容；pragma once 是广泛支持的实现设施，不能作为标准语言规则。不要在公共头放 using namespace std，因为它会影响每个包含者的未限定名字查找，并可能在以后新增重载时产生冲突。

## 4 ODR 与最小多文件项目

单一定义规则 ODR 要求同一翻译单元不能重复定义规定的实体；被 odr-use 的普通非 inline 函数或变量在整个程序中需要相应定义。类、模板和 inline 实体可在多个单元出现定义，但要求相同记号序列及相应名字查找一致等条件，不能只比较“看起来行为一样”。某些跨单元违例不要求诊断。[ODR 条件](https://timsong-cpp.github.io/cppwp/n4659/basic.def.odr)。

类定义可以位于头文件，不表示它的普通非 inline 成员函数定义也应重复放进去。类内定义的成员函数隐式 inline；类外定义则按其声明和定义规则另行判断。命名空间作用域 const 变量的默认链接属性还有例外，声明为 extern、inline 或先前已具有外部链接会改变结论；共享常量应选明确的接口形式，而非依赖同名变量偶然得到相同地址。

拆分本例时，把 `int twice(int);` 放入有包含保护的 `twice.hpp`，定义放入 `twice.cpp`，main 放入另一 cpp；两个 cpp 都包含该头，然后一次命令编译并链接两个 cpp。包含保护只防止同一翻译单元重复包含，不能让普通函数定义合法地出现在多个单元。不要把 `#include "twice.cpp"` 当作正常项目组织方式。

## 5 诊断入口与排障次序

读错误时先找最早的一条有意义诊断及其位置，后续报错可能只是连带结果。未声明标识符通常在编译阶段；undefined reference 常指没有提供匹配定义、漏编源文件或链接库；multiple definition 常指违反定义组织规则。它们是典型工具现象，错误文字随工具链变化。

明确写 `-std=c++17`，不要依赖编译器默认版本；升级到 C++20 同时要检查编译器和标准库能力。警告帮助发现可疑转换与未使用对象，但无警告不等于无未定义行为。遇到问题先缩减到可复现的翻译单元，再核对构建命令、包含路径、宏定义和链接输入。变量初始化见 R03，运行时边界见 R04，工程构建见 R28。

构建命令失败后不要运行上次留下的可执行文件：旧程序可能仍存在，甚至输出看起来正确。因此命令中的退出码检查在两步之间不可省略。运行时出现的消息也要区分编译器诊断、链接器诊断和程序自己写到标准错误的报告；后者必须由应用定义含义。故障记录至少保存实际命令、语言版本、首条诊断和预期结果，才能让别人复现同一个问题。
