# C++ 参考手册条目与编写规范

本手册服务两种需求：首次接触 C++ 时建立足够准确的心智模型；接手代码、选接口和排查故障时迅速找到适用规则。快速来自明确的入口、短条目和索引，不来自省略前置条件。

## 篇幅与覆盖

采用 7 篇 30 章的目录，章是检索分组，条目才是阅读单位。普通条目约半页到一页，生命周期、并发和网络机制可以使用两页。首次入门路径只读取核心条目，不强迫顺读整本。

初始排版预算为正文约 80 至 100 页，不含索引；这不是以删掉必要条件换取页数的硬上限。目录审阅后再按选定的条目数量和图表密度校准。若超预算，先减少低频功能与重复例子，保留核心规则、反例和生产故障条件。不能把三个宽泛主题强行压成一页，或者用一大张图代替语义解释。

每章的二级主题用于覆盖审核，不要求套用同样的小节篇幅。至少区分首次必读内容与后查内容，解释先修关系；不能为了整齐而每章只写三条常识。

## 语言规则条目

按需要依次提供：

- 名称、适用版本和解决的问题。
- 语法形式及关键规则；默认行为与例外。
- 生命周期、求值、转换、所有权或异常条件中的相关部分。
- 一个最小正确例子及其确定的结果；一个有明确原因的典型错误。
- 工作中的使用建议和相关条目。

避免把规则写成无条件口号。例如移动、引用绑定、初始化和异常安全都需要说明成立条件。高级术语首次出现给一句准确释义，不用拟人化比喻取代机制。

## 标准库接口条目

提供头文件、命名空间、最低版本、用途、常用签名或重载组、参数与返回值、前置条件、复杂度、失效规则、异常或错误行为、最小例子和相关符号。只展开高频接口；其余提供同族索引及官方或参考入口，不承诺覆盖全部重载。

例如容器条目必须能查到 reserve 与 resize、查找与插入、容量变化与失效之间的区别；算法条目必须能查到区间、比较器、排序或分区等前提。对标准未规定的内部结构明确标注常见实现，不能作为可移植性保证。

字符串与视图条目必须同时交代所有者和借用者的生命周期。共享所有权、线程安全、对象访问安全分别说明，不能合并成一句“安全”。版本和平台差异靠近相关结论，不藏在整章末尾。

## 系统与网络条目

使用“机制与接口边界、典型工作场景、现象、检查依据、常见误判”的结构。列出操作系统或协议前提。复杂度字段只用于适用的算法和结构，不强迫所有系统概念套用标准库模板。

区分语言保证、标准库保证、协议规定、操作系统接口和具体实现。Linux 和 Windows 的 API 不混写成同一流程；socket、TLS、线程池等能力明确指出来自何处。工具建议说明用途和适用范围，不要求用户安装或更改本机环境。

## 图表与例子

图解采用参考图片的清晰分栏、箭头和简短标签，但不把所有主题都画成时序图。优先维护可编辑 SVG 图源；机制图的说明紧邻相关规则，每图只回答一个重要问题。目录已为各章指定候选图表，正式编写时按机制需要合并，避免图数指标驱动。

代码尽量独立编译；摘录必须说明上下文。记录标准版本、平台、构建命令、预期输出和检查结果。跨平台例子与平台专用例子分开。不得运行未定义行为来证明规则；错误示例用于解释，可用诊断或安全测试展示问题，不用一次运行结果推断行为保证。

正文示例和配套源文件保持一致。将边界、失败路径、资源释放和并发退出纳入检查，不以“程序返回 0”代替语义核对。当前阶段不创建示例和图源，也不更改构建管线。

## 来源与核验

cppreference 提供分类和检索形式的参考，不复制其内容。语言与库规则根据匹配版本的标准公开草案核验；系统接口优先官方平台文档，网络语义优先 RFC，工具行为优先工具官方文档。源码与实现资料只支撑标注实现范围的结论。

引用贴近适用结论，记录版本和平台。当前公开草案可能超出 C++17/20/23 的基线，不能把新规则回填为旧版本已有。编译成功只证明特定环境下的例子通过，不能替代标准或协议依据。

## 目录确认后的实施安排

本轮由主 Agent 统一设计并审查目录，不委派正文任务。得到目录确认后再启动以下分工，正文与图源使用不同的负责范围，避免共同编辑同一文件：

- 主 Agent 负责技术基线、统一条目规范、交叉引用、图源风格、整合与最终核验；先确定 1 篇的条目粒度，再推开全书。用户不要求样章，首批正文直接作为正式内容。
- 语言与标准库 Agent 负责第一至三篇的正文与独立例子，使用 gpt-6.1-sol、high、fork_turns none。类型推导、生命周期、异常与失效规则需要较强的综合核验。
- 系统与网络 Agent 负责第五至六篇及对应平台例子，使用 gpt-6.1-sol、high、fork_turns none。操作系统与协议边界需要明确区分。
- 并发与工程 Agent 负责第四、七篇及对应例子，使用 gpt-6.1-sol、high、fork_turns none。内存模型、退出协议和排障路径需要谨慎核验。

正文部分在公共版本约束和术语确定后可并行；跨篇生命周期、所有权、内存模型和 I/O 条目由主 Agent 统一交叉检查。图源在相应条目的结论稳定后绘制，导出和版面检查在正文与图源整合后进行。不提前发布，也不把本轮目录审核视作正文完成。

## 审阅检查

目录应能回答：从哪里开始写第一个程序；规则和接口去哪里查；哪些借用会失效；容器和算法为什么选它；对象怎样跨线程安全使用；程序怎样接触 OS 与网络；工作故障先看什么证据。

本轮检查仅针对目录编号、篇章顺序、主题覆盖、阅读路径和文件完整性，不运行全书测试，不宣称正文、图表或制品已验证。目录通过后再按实际改动范围验证例子、图源、构建和排版。
