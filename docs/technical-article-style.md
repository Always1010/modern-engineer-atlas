# 技术文章与书稿风格规范

2026-10-10。根据《C++ 与计算机基础图解参考手册》的全书整改及用户逐轮确认整理。本文件维护可用于其他技术文章、教程和书稿的结构、行文、重点标注及页面样式约束。

## 使用范围与规则来源

本规范是一份可复用的编辑依据。其他文章采用时，明确引用本文件，并记录该文章自己的主题范围、技术版本、输出形式及核验方式。具体项目的新要求另行列出；同类内容在全篇采用同一规则。

本书专属的7章35节、R源ID、C++17基线、来源文件格式、构建命令及不编译运行示例的要求，见[手册编辑规范](../manuscript/cpp-reference-handbook/v1.0/EDITORIAL-SPEC.md)及[核对与重建说明](../manuscript/cpp-reference-handbook/v1.0/BUILD-NOTES.md)。这些项目参数不自动成为其他文章的要求。现有其他书稿需明确采用本规范后再按其自身结构迁移。

本规范中的颜色、字体和排版基准来自当前[手册公共样式](../manuscript/cpp-reference-handbook/v1.0/tools/handbook.css)。复用样式时还需结合[排版转换](../manuscript/cpp-reference-handbook/v1.0/tools/handbook-typography.mjs)及目标文档的结构；单独复制CSS不会自动产生编号、版本标签和英语字体标记。其他工具可用等价样式实现相同效果。

## 结构、标题与导航

- 多章书稿采用“第1章—1.1节—1.1.1主题”的层级，不再使用“第一篇第几章”作为本风格的读者编号。短文章从所需层级开始，不为凑层级增加空章节。
- 同一层级的编号与标题使用相同字体、字号、字重和基线；编号可用蓝色区分，不能缩成与标题不协调的小标签。
- 标题用具体的概念、对象、规则或任务名称。内容顺序表达学习层次，去掉反复出现的“基础操作”“机制解释”“进阶后查”等固定分类标签。
- 章首页可以提供大号浅蓝装饰数字、章名、简短导语和本章节目录。装饰数字与正文标题编号分别承担视觉和导航作用。
- 多节内容提供对应目录；交叉引用、图号、索引和PDF书签遵循同一编号体系。内部文件ID和锚点尽量稳定，显示编号可以随编排调整。
- 标题与其首段尽量放在同一页，避免孤立标题。章、节是否另起一页由具体书稿的阅读与排版要求确定，不通过局部压缩字号解决分页问题。《C++ 与计算机基础图解参考手册》每章、每节另起一页，小节随正文连续排版。

## 行文与内容组织

先说明概念或对象是什么、解决什么问题，再给正常写法、结果和条件，最后解释机制、差异与例外。单个段落应新增定义、分类、操作、结果、条件或机制，避免仅换句话重复已有信息。

首次正式定义术语时给出中文名称，必要时补充英文或缩写，再给一句明确的定义。英文译名不是加粗理由。技术术语使用一致译名；普通英语、代码符号和版本号按各自语义标记，不把正文中全部英文当作代码。

解释具体对象或接口时，按实际需要交代用途、适用版本、输入或参数、结果或状态变化、前提及短例。操作说明写清准备、操作和结果；流程用步骤、流程图或时序图表达。不同主题不强行套用所有字段。

删除泛泛的工程提醒、重复的限制和无信息量的引导语；保留会影响理解或正确性的条件。一个基础定义应有主要维护位置，其他位置可以回链，但影响当前操作的条件仍须就地说明。语言标准、库规则、常见实现、操作系统与协议保证必须区分。

## 重点标注：先判断语义，再选择样式

重点标注分为三个问题：它是什么类型的内容，它在当前句中承担什么作用，以及它出现在哪个区域。不能只根据词语是否在术语表里决定加粗。

### 正文加粗规则

允许加粗的两类位置：

1. 正在给出概念或代码符号的定义、核心语义。只加粗被定义的中文术语或符号，不连带加粗整句及括号中的英文译名。
2. 正在明确比较同级概念、写法或结果。选择比较对象或关键差异结果进行强调，同一组对象使用相同处理；避免把对象、条件和结论全部加粗。

其余位置使用普通字重，包括术语的重复提及、一般说明、举例叙述、英文释义、条件、限制和补充信息。首次出现只是检查定义的机会，不自动触发加粗。不要按关键词列表批量替换，不设置每段必须加粗几处的数量指标，也不把整句或整段加粗。

因此，同一术语在定义句中加粗、在后续说明中不加粗是符合规则的；同一比较句里的同级对象一个加粗、另一个不加粗，需要复查是否漏标。

### 英文、代码符号与版本

正文中的语言关键字、类型名、API、变量名或短表达式使用行内代码标记。普通行内代码统一蓝色、普通字重；处于定义或明确对比位置时，才额外加粗。普通英文名称和括号里的英语释义采用正常正文英文样式，不附代码底色、边框或等宽字体。

例如，正文里的 `constinit`、`constexpr`、`auto`、`decltype(auto)` 都按代码符号处理，不应有的蓝色、有的完全没有代码样式。是否加粗仍取决于当前语义，不能因为它们都是语言关键字就全部加粗。完整语句或带较多标点的表达式作为一个行内代码单元处理，不只挑其中一个词着色。

段首用于限定整段适用版本的“C++20”使用统一的蓝灰色细边框标签。句中介绍历史、进行版本比较或举例提及的“C++17”“C++20”使用普通英文样式。差别由用途决定，不由具体版本数字决定；同样的用途应有同样的外观。其他技术的版本提示沿用相同判断方式。

### 表格与其他区域

表格正文统一普通字重、深色文字，术语及代码都不使用强调色、加粗、标签底色或其他重点装饰。代码仍可保留其语义标记，但显示为表格正文样式。表头可以使用结构性加粗和浅蓝底色。

标题、表头及图标题的结构字重不受正文加粗规则限制。代码块的语法着色属于代码阅读辅助，不等于正文重点标注。代码前提说明只强调实际层次，不能通过重复加粗“头文件”“版本”等标签增加噪声。

### 标注示例

下面的例子用于判断正文加粗位置；其他术语按同样的语义规则处理。

- 定义：**初始化**（initialization）建立新对象的初始状态。后文的“初始化类别描述所采用的语法或语义过程”保持普通字重。
- 定义：`consteval` 声明**立即函数**（immediate function）。这里在定义立即函数；若某个条目专门解释 `consteval` 本身，也可以改为强调该符号，避免同一句中重复强调多个对象。强调代码符号时使用 ``**`consteval`**`` 这样的源码标记。
- 定义：花括号初始化会拒绝规定的**窄化转换**（narrowing）。另一句中的“转换条件仍须逐项判断”不因表达限制而加粗。
- 定义：**聚合**（aggregate）包括数组和满足规定条件的类。后续示例中的聚合一词保持普通字重。
- 对比：**默认初始化**类通常调用可用默认构造函数；**值初始化**还涉及规定的零初始化过程。两个同级对象使用同样字重，后面的条件和结果不再全部加粗。
- 普通限制：`constinit` 不保证变量可用作常量表达式，且不能与 `constexpr` 在同一声明中组合。两个代码符号保持相同的普通行内代码样式。
- 普通补充：静态存储期标量没有显式初值也先经历零初始化，不能把这项保证用于普通自动局部变量。此处是补充条件，保持普通字重。

## 代码片段及说明

代码用于解释语法、接口、操作或关系，先交代用途和必要前提，再给片段，随后说明结果或状态变化。不要求每个短例都写完整 `main`；完整程序或小工程可放在配套文件中，正文链接到它并解释重点。

不要添加或重复解释“独立片段”“声明摘要”“承接上文”“执行路径示意”等固定类别标签。确实需要说明节选性质时直接写具体信息，例如“下面省略了错误处理”或“此处只列与调用有关的声明”，避免让文字只是解释一个已经删除的标签。

保留实际依赖：头文件、已有对象、作用域、版本、平台、输入、共享定义、线程角色、初始化关系及省略范围。相邻代码块不能默认连续执行；承接关系和可替换方案需要写清。并发代码不承诺未被保证的输出顺序，平台相关结果明确环境。

操作短例通常包含3—12个有效语句，机制例通常为10—30行。这是控制阅读负担的参考范围，不能据此删除必要逻辑。短代码尽量完整放置；长代码可以按逻辑分页。调整排版不能改变代码文本、缩进或空行含义；不为换页删掉报文中有意义的空行。

示例是否执行以及执行环境由具体项目约定。静态核对、资料核对和实际运行分别报告，不把一种核验说成另一种，不使用未定义行为的运行结果证明语言规则。

## 页面样式、字体与颜色

视觉层次通过标题大小、间距、细线、代码区和章首页建立。正文保持清晰的连续阅读，不把每个概念做成卡片。全篇使用共同样式，避免为某一章临时更换字号、颜色或间距。后续调整共同规则时同步更新本规范和实际样式实现，避免说明与制品脱节。

### 颜色基准

| 用途 | 基准值 | 使用方式 |
| --- | --- | --- |
| 正文深色 | #26364a | 正文及表格内容 |
| 主蓝色 | #365f9c | 编号、普通行内代码、代码关键字 |
| 代码背景 | #f1f5fc | 浅蓝底色，配细边框 |
| 表头背景 | #eaf0fa | 仅用于表头区域 |
| 辅助线 | #cad8ec | 表格分隔、目录与层级细线 |
| 类型紫色 | #7053a0 | 代码块中的基础类型 |
| 数字棕色 | #8b6740 | 代码块中的数字 |
| 字符串棕色 | #805b44 | 代码块中的字符串 |
| 注释灰色 | #707887 | 注释、图注及次要说明 |
| 章首页装饰数字 | #dfe8f6 | 大号浅蓝数字 |

不使用绿色作为本风格的装饰、编号、版本提示或代码类型色。图示沿用蓝色、紫色及必要的中性色，不另起一套配色。信息差异同时由文字、线型或布局表达，保证黑白输出也能辨认。

### 字体基准

| 区域 | 首选字体 | 规则 |
| --- | --- | --- |
| 中文正文 | SimSun／宋体 | 正常字重，适合连续阅读 |
| 标题及中文强调 | Microsoft YaHei／微软雅黑 | 标题与编号协调，强调由语义决定 |
| 正文英文及行内代码 | Segoe UI | 普通英语不使用代码块等宽字体 |
| 围栏代码 | Consolas | 保留等宽对齐及语法着色 |
| 表格 | Microsoft YaHei／微软雅黑 | 正文普通字重，表头结构性加粗 |

缺少首选字体时选择覆盖所需中英文字符的同类替代字体，并复核换行和分页。PDF应嵌入实际使用字体；字体及素材许可遵循目标项目的现有要求。

### 屏幕与打印基准

A4正文以10.7pt、约1.62倍行高为起点，表格和代码以9pt为起点；页边距上21mm、左右18mm、下19mm。节标题约23pt、主题标题约13.5pt，编号继承标题参数。字号和间距需要结合目标内容的实际页图校准，不能为追求页数持续缩小文字。

屏幕版正文以17px、约1.85倍行高为起点，窄屏可调整为16px。正文容器与长标题可以换行；表格和代码在必要时允许局部横向滚动，不能拖宽整个页面。屏幕和打印分别设置规则，共用语义和配色。

续表重复表头，表格行尽量不拆页。宽表和长段单元格先考虑拆分；图和图注尽量同页，文字不能重叠、裁切或小到无法辨认。章节留白服务于结构，不产生意外空白页。

## 表格、图示与资料链接

表格用于比较和查询，同类实体作为行、一致属性作为列，通常3—4列。详细解释、完整签名和短例放在条目正文里；流程优先使用步骤或图示，不强行塞进表格。

图示需要明确回答分类、结构、过程、时序或状态变化中的一个问题。优先使用可编辑SVG并提供title／desc；图中标签与正文一致，图注解释必要边界。图的数量不作为质量指标，删除图时同时清理引用。

资料依据移入对应文章的来源记录，保留标题、链接和适用位置；不在段尾堆放外部资料链接，也不在每章末重复一串来源。配套源码、内部相关条目以及完成当前操作需要的工具或官方入口可以按实际用途保留。版本提示是适用范围信息，不是资料链接装饰。

来源形式可按文章项目选用来源文件或维护台账；需要读者就地查证、署名或遵循出版引用规则时，保留必要引用。减少阅读噪声不能删掉引用依据或许可信息。

## 审校与复用流程

1. 明确采用本规范及项目补充约束，整理标题层级和术语定义位置。
2. 先审查内容和语义标注：正文强调逐句判断，代码符号一致标记，表格正文无重点装饰，代码说明保留必要前提。
3. 用共同样式生成代表性内容，至少覆盖标题、定义、重复提及、对比、版本提示、表格、代码和图示。核对后应用到全文。
4. 核对源稿与制品中的代码、图示、标题、锚点、目录、交叉引用及页码；依据本次改动范围安排检查。
5. 检查打印页图及窄屏阅读，复核裁切、乱码、空白页、孤立标题、表头重复、图注和长行。PDF检查字体嵌入。
6. 记录实际核验范围及结果，区分当前规范、项目参数和历史验收数据。不得把本书的260页、代码块数量或页码当作新文章的验收目标。
